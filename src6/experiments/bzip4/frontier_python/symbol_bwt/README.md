# Grammar-root symbol BWT experiment

This directory is an isolated, pure-Python reference family.  It tests one
bounded hypothesis: a charged pair grammar can reduce a raw block to literal
and rule root IDs, after which BWT/MTF/RUNA-RUNB may expose local repetition
that a global static entropy model misses.  The decoder uses a canonical
Huffman walk, a bounded inverse BWT, and flat grammar expansions; it does not
use a native or external decoder.

The transform is established prior art, not a novelty claim.  Relevant
primary references are [Grammar-based precompression speeds up
BWT](https://www.cs.helsinki.fi/u/tpkarkka/publications/spire2012.pdf),
[Word-based Burrows-Wheeler transformation](https://doi.org/10.1016/j.ipm.2004.08.009),
and the original [Burrows--Wheeler report](https://www.hpl.hp.com/techreports/Compaq-DEC/SRC-RR-124.pdf).
The 2025 grammar implementation is imported read-only; this directory does
not alter the grammar or earlier `bwt_context` families.

## Wire and decoder state

`SBW1` stores a complete fixed grammar model (`GMD1` DAG with literal IDs
`0..255` and backward rule references), a dense Huffman event-length table,
and a 36-byte record for every raw block.  A record charges the payload
offset/length, raw length, root-token length, MTF-event length, cyclic-BWT
primary, CRC-32, and exact valid bit count.  The payload begins with a raw or
coded mode byte.  Metadata CRC covers the zeroed-CRC header, both model blobs,
and the directory; each decoded raw block has its own CRC.

The MTF list is initialized to the full known alphabet
`0..255+rule_count-1`; no unstored per-block alphabet or external dictionary is
used.  A non-zero MTF rank `r` is event `r+1`; zero runs use bijective RUNA
(`0`) and RUNB (`1`).  There is no hidden end marker: event and root-token
counts are explicit in the directory.  `prepare()` validates the frame,
builds the Huffman tree and flat rule table, and reports those costs.  It does
not precompute a native MTF cache.  Each coded root symbol performs one MTF
decision and one bulk expansion copy; output bytes are copied from the flat
table rather than generated by inference.

The decoder rejects malformed/truncated frames, non-zero Huffman padding,
extra body bytes (`len(body)` must equal `ceil(valid_bits/8)`), invalid primary
indices, impossible event/root lengths, forward grammar references, CRC
mismatches, and block indices outside the directory.  The grammar's bounded
expansion limits remain in force.

The builder's internal consistent-pair root streams are encoder diagnostics;
this family intentionally re-tokenizes each raw block with the finalized
grammar's deterministic longest-match trie before BWT.  The measured result
therefore covers a grammar-family plus parser choice, rather than silently
claiming that BWT ran over transient pre-prune builder streams.

## Model scope and API

```python
from symbol_bwt import train, encode, decode, decode_block, prepare

model = train(training, block_bytes=16 * 1024, max_rules=8192,
              max_passes=24, pair_policy="consistent")
frame = encode(data, model, 16 * 1024)
assert decode(frame) == data
prepared = prepare(frame)
assert prepared.decode_block(0) == data[:16 * 1024]
```

`train(..., input_fit=True)` builds a complete encoder-derived model over the
input.  This is ordinary two-pass compression, not a held-out generalization
claim: the grammar and event table are both stored in every frame.  The
default `input_fit=False` marks a model as training scope for a separate
holdout.  Literal escapes and the full MTF alphabet preserve arbitrary bytes,
including invalid UTF-8 and random data.

`codec.metrics()` is encoder-side accounting.  `frame_metrics()` reports
complete bytes, header/model/directory/payload decomposition, event bits and
padding, grammar expansion bytes, model alphabet, root/event counts, and
logical prepared-tree/MTF scratch estimates.  Python nanosecond timings are
prototype timings only and do not establish future Zig/native decoder speed.

## First size gate

The captured screen is exactly 262,144 bytes `[1 MiB, 1.25 MiB)` from each
pinned projection, with an input-derived consistent-pair grammar (8192 rule
cap, 24 passes) and all model bytes charged.  Native bzip3 controls are the
matched complete frames retained by the common protocol.

| corpus | 16 KiB symbol-BWT | 16 KiB bzip3 | delta | 64 KiB symbol-BWT | 64 KiB bzip3 | delta |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| FreeDict English--Spanish | 33,032 | 36,428 | −3,396 (−9.32%) | 31,273 | 27,239 | +4,034 (+14.81%) |
| GCIDE | 75,386 | 72,885 | +2,501 (+3.43%) | 72,640 | 58,700 | +13,940 (+23.75%) |
| OMW Japanese | 35,566 | 36,163 | −597 (−1.65%) | 31,867 | 22,279 | +9,588 (+43.04%) |

All six rows passed full and every-independent-block roundtrips.  The raw
subprocess streams and status records were written before JSON parsing in
`results/raw/size-screen-consistent-r8192-p24/`; the aggregate ledger is
`results/size-screen-consistent-r8192-p24.json`.  The first-row retry is kept
under `results/raw/first-freedict-16-v2/` as independent evidence.  The code
hash recorded in each row covers `codec.py`, `worker.py`, and `screen.py`.

The 16 KiB rows are within the provisional bzip3+10% promotion bound; all 64
KiB rows fail it.  This is therefore a promising small-boundary storage
screen, not an acceptance result.  No 8 MiB or timing lane is claimed here;
promotion requires the coordinating serial gate.

## Rejected/retained ablations

* `overlap_greedy` grammar candidates were measured as a reference and
  rejected for this lane: on the same screen it retained 1,976/2,836/2,886
  rules and produced 42,304/86,495/48,582 bytes at 16 KiB for
  FreeDict/GCIDE/OMW, versus 33,032/75,386/35,566 for the consistent-pair
  model.  Those figures include grammar/event models and directories.
* The earlier raw-byte BWT family is not substituted as a free control; its
  own charged ledger is in `../bwt_context/RESULTS.md`.  This experiment's
  full root alphabet deliberately pays for grammar IDs and avoids its
  unstored local alphabet mask.
* Static-Huffman grammar payloads without BWT were retained as a diagnostic
  in the parent grammar ledger.  This family replaces the grammar event model
  with the charged root-BWT event model, so the old grammar Huffman length
  table is not serialized redundantly.
* rANS, local model selectors, and recursive rule expansion are not hidden in
  this result.  They are separate future ablations and would require their
  own complete model/state accounting.

The development screen alone did not justify a full-size promotion; the
coordinating parent later authorized the bounded size-only partial below.

## Authorized full-size partial

The coordinating gate authorized a size-only full `[1 MiB, 9 MiB)` run with
8192 rules, 64 passes, and consistent pairs.  The first FreeDict/16 KiB child
completed at 814,375 B versus its 1,189,002 B bzip3 control (−31.5%).  After
the decoder-bound hardening, the active GCIDE child completed both boundaries:

| corpus | 16 KiB symbol-BWT | 16 KiB bzip3 | 64 KiB symbol-BWT | 64 KiB bzip3 |
| --- | ---: | ---: | ---: | ---: |
| FreeDict English--Spanish | 814,375* | 1,189,002 | 778,935 | 899,408 |
| GCIDE | 1,860,752 | 2,362,319 | 1,826,256 | 1,905,560 |
| OMW Japanese | 778,911 | 1,124,142 | 642,092 | 674,384 |

`*` The FreeDict/16 KiB child predates the final parser/block-count safety
edits; the other captured rows also retain their exact historical code hash in
their raw JSON.  All six complete frames decode under the current parser, but
the parent serial harness should regenerate the matrix under the current
source hash before final timing/acceptance.  Captured frames and raw
subprocess records are listed in `SOURCE_MANIFEST.json`.
