# Recent model-driven compression: evidence and one low-model-cost experiment

Research pass: 2026-10-01 UTC. GitHub HTML/raw/release sources were reachable; `api.github.com` and `bellard.org` were blocked by the configured egress proxy. I did not retry arXiv or the blocked Bellard site. Source details below are pinned where possible. Reported performance tables are project claims, not independently reproduced results.

## Primary-source observations

### Google DeepMind, *Language Modeling Is Compression* (ICLR 2024)

- Official repo: [google-deepmind/language_modeling_is_compression](https://github.com/google-deepmind/language_modeling_is_compression), inspected at commit [`b5c8f8a63349d0a2604367d47df4a7c79db52890`](https://github.com/google-deepmind/language_modeling_is_compression/commit/b5c8f8a63349d0a2604367d47df4a7c79db52890), committed 2024-08-28. Its README identifies the ICLR 2024 paper and links [arXiv:2309.10668](https://arxiv.org/abs/2309.10668); I used the repo, not an arXiv fetch.
- The reference compressor codes the original input bytes as 0–255 symbols with model-predicted distributions and arithmetic coding ([`compressors/language_model.py`](https://github.com/google-deepmind/language_modeling_is_compression/blob/b5c8f8a63349d0a2604367d47df4a7c79db52890/compressors/language_model.py)). Its `params.npz` model weights are loaded outside the compressed payload; the repo says Chinchilla 70B weights are not provided. Thus compressed bytes alone are not a self-contained codec/model selection. The paper/repo is strong evidence that learned prediction can transfer across modalities and that tokenizer/model choices affect code length, but it does not supply a small decoder-free model representation.
- The code exposes a practical speed/reproducibility constraint: the encoder can compute logits for the full sequence in one pass, while lossless decoding reconstructs tokens autoregressively and recomputes predictions for every growing prefix. Its “slow lossless compression” path explicitly uses O(n²) prefix evaluations to match decoder conditionals. Any direct neural-probability coder inherits exact model/version/logit agreement and autoregressive decode cost.

### `llama-zip` (active 2024–2026 GitHub implementation; not an academic result)

- Repo: [AlexBuz/llama-zip](https://github.com/AlexBuz/llama-zip), inspected at commit [`d682e5edc73cee3535a22f3699cf62e5ca6f6264`](https://github.com/AlexBuz/llama-zip/commit/d682e5edc73cee3535a22f3699cf62e5ca6f6264), committed 2026-06-15. The README reports tests with Qwen3.5-35B-A3B-Base Q8, Phi-3.1-mini Q4, and Llama-3.1-8B Q4; those are large external GGUF models. Its displayed Calgary table is its own reported benchmark, not a byte-for-byte independently reproduced comparison.
- The implementation uses model token IDs + arithmetic coding, predicts with `temp=0`, quantizes softmax probabilities to integer cumulative frequencies at scale 2^32 with a minimum frequency of one, and adds EOS. It uses configurable context overlap to regenerate predictions beyond the model window. It maps invalid UTF-8 through private-use code points and incrementally restores byte sequences, so the source explicitly tackles arbitrary-byte roundtripping through a text tokenizer ([`llama_zip.py`](https://github.com/AlexBuz/llama-zip/blob/d682e5edc73cee3535a22f3699cf62e5ca6f6264/llama_zip.py)).
- Important accounting gap for comparisons: its CLI asks for a model path and identical overlap at both ends; the compressed stream does not pay for model weights/tokenizer/runtime. Decode also relies on reproducing model logits and tokenization exactly. This is a useful model-assisted upper-bound/reference for text prediction, but it does not meet the “small/no huge decoder model” target.

### `cmix` v21 (strong classic-context reference, older release)

- Release: [`v21`](https://github.com/byronknoll/cmix/releases/tag/v21), release page dated 2024-09-16 and pointing at commit [`c443679c0773b8ae5b05423827804063d82ae7a8`](https://github.com/byronknoll/cmix/commit/c443679c0773b8ae5b05423827804063d82ae7a8). Its checked-in `README` says “version 21,” dated Sept. 10, 2024, recommends at least 32 GB RAM, and explicitly warns `-Ofast -march=native` can cause cross-computer incompatibility from floating-point differences; `-O3` is suggested for compatibility.
- The release history documents a multi-model mixer (LSTM and several PAQ/PPM/indirect/interval/bracket/match contexts and successive community ports), not one learned tokenizer. Useful lesson: diverse contexts can complement each other, but the memory/decoder/runtime footprint and deterministic arithmetic are first-class costs. cmix is a valid conventional compressed-output-size reference under the usual shared-code assumption. Its bundled model, 32 GB recommendation and runtime differ from this project's per-frame delivered models and bounded native decoder. It has not been benchmarked here; any future comparison should report those resource and model assumptions explicitly.

### Nearby 2026 GitHub names that are not equivalent codecs

- [TokenZip/TokenZip](https://github.com/TokenZip/TokenZip) is a semantic shared-memory/pass-by-reference protocol using embeddings/vector quantization and remote retrieval. Its stated payload reductions are not lossless self-contained byte compression: a pointer requires the shared payload service/state and semantic reconstruction. Exclude it from byte-compressor baselines.
- [facebookresearch/zest](https://github.com/facebookresearch/zest) is a Zstandard-based text classifier (its README cites a 2021 workshop), not a recent learned lossless compressor. It is outside the requested comparison.

## Actionable lessons for this dictionary codec

1. **Make the delivered frame the objective.** Neural work shows predictive probabilities can be strong, but model weights, tokenizer, version, and normalization are often assumed external. Here optimize `header + phrase grammar/lexicon + ordering/classes + entropy tables + root symbols + typed parameter streams + restart records + checksums` as delivered. Every proposed phrase or feature must beat the baseline after all those bytes are serialized. Refit and re-evaluate the complete frame after phrase selection; `-log p` alone is not a byte-accounting objective.
2. **Do not put an LLM in the decoder loop.** `llama-zip` and DeepMind’s coder depend on exact decoder-side model predictions. Runtime, weights, tokenizer, floating-point mode, context policy, and EOS/framing must match. That is contrary to self-contained small decoding. Use model predictions only to propose or rank exact source-span candidates on the encoder, then transmit selected phrase expansions/typed values and code the resulting IDs with the existing static rANS model. The decoder reads the phrase table and integer entropy models only.
3. **A credible next experiment: encoder-only morphology/phrase proposal, exact frame-priced selection.** On development-only corpora, create a candidate lattice of exact byte spans from (a) current RePair phrases, (b) supervised UD TRAIN-only lemma/features and affix boundaries for Finnish/Turkish/Arabic, and optionally (c) a frozen teacher’s high-confidence subword/phrase proposals. Keep each proposed token’s expansion as the exact original UTF-8 bytes; byte fallback handles invalid or unseen spans. Use exact DP over the union lattice to select parses while including token ID cost plus typed morphology/copy-parameter cost. Then iteratively refit static context/rANS tables and score a completely serialized frame. Decoder needs no analyzer/teacher: it receives the chosen phrase bytes, parse symbols, exact suffix/allomorph/copy parameters, and entropy models. Compare against RePair-only and current copy-token baselines with identical restart policy, full-frame bytes, and fresh decoder roundtrips. This is a falsifiable experiment: language-aware candidates help only if their measured savings exceed phrase/affix tables and parameter cost.
4. **Test scripts as exact surfaces, not normalized text.** For Latin, morphology proposals can share stems and suffix families; agglutinative words may offer productive suffix sequences, while Arabic templatic roots need explicit stem/allomorph candidates. For CJK, allow multi-scalar dictionary phrases because whitespace boundaries are absent. For every script, preserve source bytes (combining marks, Arabic presentation/diacritics, case, punctuation, and Unicode normalization form) through literal phrase expansions or typed exact-byte residuals. Never rely on a decoder-side Unicode normalizer or tokenizer.
5. **Use integer/deterministic probability definitions in the format.** The cmix README’s cross-machine floating-point warning is directly relevant. Keep decoder tables integer and serialized, define canonical normalization/tie handling and parameter varints, and make CRC/hash scope exact. Encoder-only floating scores may propose parses, but the final chosen parse and integer table must be stored/reproducible from the frame.

## Limits

This pass verifies public GitHub source and release metadata, not paper PDFs, external model binaries, or claimed compression tables. There is no official `ts_zip` source verification because its host is blocked. `llama-zip` numbers include shared model assumptions and are not compared to the project’s corpus/harness. The morphology/teacher lattice is a proposed experiment, not an established compression improvement; existing small UD screens already show that simple suffix/subword IDs can lose once their lexicon is charged.
