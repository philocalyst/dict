# Compression experiment space and next tests

Scope: inventory source code and **development evidence only**, through 2026-10-01. This is a map of finite families already explored and promising changes in representation. It excludes final-split benchmark outcomes and does not claim that the general search space is exhausted. Raw evidence and method details remain in the linked experiment reports.

## Problem boundaries

Three related workloads need separate ledgers and success claims:

1. **Byte-exact stream compression** of complete projected dictionary content or prose. Every input byte, block boundary, frame field, and checksum is part of the result.
2. **Word inventory coding** where repeated word forms become symbols. A smaller word table alone is not a compressed-file win: pay for ordering/rank bridges, form IDs, occurrence payload, and the grammar that constructs forms.
3. **Typed dictionary pages** where the packet schema is known and semantic validation must still pass. Compare exact native values and complete compressed pages; do not describe a typed projection as byte compression unless its source bytes are also preserved.

A result from one lane does not transfer automatically to the others. In particular, a representation that wins on a sorted list may lose on prose, and a graph that saves repeated schema values is not a general-purpose byte codec.

## Existing references from development work

- The original native lexical CLI produced 579,202 / 1,324,034 / 374,217 bytes on retained 8 MiB FreeDict / GCIDE / OMW inputs. The stronger historical byte-MDL LaneA+M results were 564,416 / 1,276,838 / 330,148 bytes. A fresh faithful M learner produced 564,416 / 1,279,033 / 331,721; the small GCIDE/OMW drift is retained explicitly. Joint raw-root context reparsing reached 558,643 / 1,273,132 / 330,282 after selecting among four complete native passes. These are development results, not final-corpus claims. See [`wordgrammar/wgp6/RESULTS.md`](../../../experiments/wordgrammar/wgp6/RESULTS.md) and the lifetime/restart compatibility evidence in its `research/` directory.
- The bzip3 matched-restart and whole-file controls are distinct. WGP5's 8 MiB development frames beat matched 64 KiB bzip3 on OMW (−24.59%) and GCIDE (−21.16%), but were +6.2% on multilingual prose. It uses a bounded shared grammar, static finite-state source, and exact output-surface copies; see [`wordgrammar/RESULTS.md`](../../../experiments/wordgrammar/RESULTS.md). The standalone SBWT development report shows a related size win on 8 MiB dictionary content and a loss on its prose lane; it is a separate WSB2 wire and decoder ([`wordzip/README.md`](../../../experiments/wordzip/README.md)).
- Earlier bzip4 frontier research found symbol-BWT plus a bounded consistent-pair grammar smaller than matched bzip3 on its 8 MiB screens, but slower in Python and still larger on three untouched 1 MiB / 64 KiB cases. Those measurements motivated a native composition; see [`bzip4/frontier_python/RESULTS.md`](../../../experiments/bzip4/frontier_python/RESULTS.md).
- Typed lexical-page DAG and recursive shape workloads now preserve complete native values, varied senses, recurring structures, duplicates and language families. Raw rich128 DAG pages fall from 423,758 to 193,786 bytes, but complete bzip3 pages grow from 36,457 to 85,336. The natural 512-entry Japanese development DAG also grows after compression. Recursive shapes and literal-lane transposes do not recover a complete-frame win. Root-prefix splitting plus exact cold-field constructors does: 127,884 versus 136,947 bzip3 bytes on that Japanese development fixture, while rich128 still grows by 4.22%. These are separate typed representation results.

## Search sequencing and interpretation

Search capacity, rule threshold, class width, code precision, maximum fragment length, and parse refit order **after** the representation is fixed. Those are useful encoder search knobs, but not a new representation. A full-frame auto selector may choose among fixed trials only if its complete candidates share one global policy and the encode-time cost is reported. Do not promote “best per corpus” settings as one codec.

Several repeated mistakes are now explicitly guarded against:

- A lower root count, smaller stem table, fewer words, or lower order-zero entropy is not a result until all charged models and the actual context-coded payload are counted.
- A training vocabulary, rank remap, normalization, edit label, grammar table, copy parameter stream, selector or reset state cannot be assumed shared. Exact literal fallback remains available.
- Matched independent restarts and one-frame whole-file compression answer different questions. Report both separately; BZ4 v3's prior-delta replay extraction is also different from independent restart decoding.
- Screen clocks collected while agents share CPU are diagnostic only. Final speed evidence needs a global quiet window, fresh processes, paired order, and separate encode/search, full decode, preparation, cold extraction and retained extraction scopes.
- A semantic graph must pass all existing source equality, typing, multiplicity and work-bound checks. A byte codec must fresh-decode the exact source and independently decode each restart.

## Fresh representation axes, not another capacity sweep

### 1. Encoder-expensive, decoder-fast context distillation

Use the current exact word/event IDs as symbols. On development data, cluster words into a small number of **distributional classes** using their observed next-symbol distributions, then distill longer histories into a deterministic sparse context automaton. An expensive encoder may merge states by MDL or a held-out-on-development split; the reader only loads the delivered transition table and static integer entropy rows. The fallback state handles unseen histories, and raw bytes remain available for unseen words.

This is distinct from WGR's current previous-source-class source: the distilled state explicitly summarizes bounded multi-symbol history, while WGR's delivered classes describe local successor distributions. The exact word→class table, automaton states/transitions/escape, each row's frequencies, class-conditioned word/byte payload, startup table memory, reset state per independent block and all frame records must be charged. Compare one fixed state budget family by complete bytes and reader work; reject early if model bytes erase the payload gain or if sparse-transition lookup grows decoder work beyond the target. First test 256 KiB/1 MiB development slices from FD, GCIDE and OMW plus one UD script/prose lane, then expand only a cross-corpus survivor. Do not ship or assume neural weights; offline search may be expensive, decoder inference is a bounded integer table lookup.

### 2. Generated forms as transient past-cache entries: narrow implementation rejected

The stem/tail probe loses because it splits recurrence into two IDs and cannot exploit the old codec's cheap repeated whole-word references. Test a new `GEN` event: emit a stem plus exact tail/edit operands, materialize the reconstructed bytes as a transient token in the existing bounded past ring, and allow later occurrences to use the normal PAST distance tiers. No permanent NAME is needed for a generated form that recurs in the block; literal or ordinary definition fallback remains exact. Reset state at each independent restart.

The implemented standalone previous-word splice/cache wire was about five times larger than its development reference. A subsequent MDL oracle found only 37–55 bytes of 1 MiB saving for the narrow standalone-hapax removal hypothesis before paying generation operands. That kills this implementation and narrow hypothesis, not every possible transient-form coder. Evidence is in `wordgrammar/wgp6/research/gen_transient/`. Any different attempt must still pay GEN/escape, edits, cache insertion/control, distance classes, delivered models and restart state.

### 3. Exact native cost frontier for spelling decisions

A low-risk encoder-only test closes known WGP6 proxy gaps. Extend spelling DP state to include child count and terminal successor class; charge ARITY(child count) plus the true state-dependent NAME path at the terminal. Include one-time activation of every retained fragment, amortized over selected uses, while still charging every stateful reference occurrence. Refit the actual native model after each parse and choose only by complete frames. This changes no decoder format.

The complete ledger is literals + fragment definitions + ARITY + body references/CUTs + NAME + activation + occurrence/past events + all fitted tables, deltas, payload, block directory and checks. Do not count a price-matrix improvement alone. If this does not beat the current maximal graph by at least 0.5% on two of the three 1 MiB development dictionaries, stop before 8 MiB; if it passes, repeat all three 8 MiB development frames and measure encoder search time separately.

### 4. Typed recursive shape programs for dictionary pages

For the typed-page lane, go beyond hash-consing exact strings/composites: learn a compact recursive shape program whose terminals are typed literal lanes and whose nonterminals encode repeated child-type/layout patterns. Encode each page's root list and all literal holes, then reconstruct the original validated Entry values. This is a schema-aware page format, not a general text codec. Compare against flat packets, exact shared-node DAG, and adaptive complete-frame minimum. Charge program opcodes/arity/type transitions, literal lengths/bytes, root ordinals, offsets, page headers/checksums, compressed page data, and reconstruction/work bounds. Reject if exact equality fails, a complete compressed page grows outside exact-repeat controls, or the MDL selector is not included in the frame/report. Sweep page order only with the full per-page remap cost.

## Staged experiment and stop plan

1. Freeze one source/input manifest per new representation. Use existing development splits only. Define the complete-wire objective and a byte-for-byte oracle before writing a new learner.
2. Screen 256 KiB or 1 MiB first on FD, GCIDE and OMW plus an actual multilingual/script lane. Keep separate ledgers for model, identifiers, payload, restart costs, encoder search and decoder state/work. Test only one representation hypothesis at a time.
3. Reject a family early if the charged 1 MiB frame loses all three lexical baselines, if model plus parameter cost exceeds theoretical source savings, or if it violates exact-byte/typed semantics or resource bounds. Avoid another sweep over 10 capacities after a representation's accounting already fails.
4. Promote only a family with at least 1% complete-frame gain in two dictionary families and nonnegative weighted development gain across selected script/prose lanes. Expand to 8 MiB development inputs, then every-block fresh decode/extraction and adversarial format validation. Any final evaluation occurs only after source, dependencies and policies are frozen.
5. Run timing only in a globally quiet serial window. Report candidate search/encode, full decode, cold model preparation, first/middle/last block access and memory separately. Do not convert concurrent clocks into speed ranks.
