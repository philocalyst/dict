# LEX6 benchmark and evidence harness

This directory contains the independent harness for the first LEX6 comparison.
It is deliberately outside `src6` production code and does not alter any
format or query API.  `run.py` compiles the harness with two explicit module
roots: the live LEX6 source and the frozen LEX5 borrowed-core source
(`experiments/frontier/lex5-20260909/borrowed-core/freeze-20260912/source`).

The default run is a no-clock smoke/prepare run.  It builds and opens both
archives, performs complete lookup/prefix enumeration, loads every LEX6 entry,
renders the typed definition, and checks the old source-backed renderer.  It
also runs LEX6 `verifyAll` and records complete artifact bytes and hashes.  No
timing API is called unless the process receives the exact explicit gate
`--quiet-gate ROOT-EXPLICIT-QUIET-GATE`.  The Python wrapper has the same guard.

## Matched projection

The primary workload has `N=2048` entries with unique stable text identities
(`entry-0000000`, ...), unique headwords (`term-0000000`, ...), and one
definition per entry.  A deterministic mixed distribution uses three
repetitive definitions for every one prose definition; `--distribution`
selects `mixed`, `repetitive`, or `prose`.  The same generated bytes are used
for both lanes.  LEX6 stores an `Entry` with one typed `definition` item.  The
frozen LEX5 adapter receives the equivalent `model.Input`: one `.entry` record
with `.written` and text `external_id`, one `.definition` record with
`.written`, one headword key, and source-document occurrences/bindings that
make the old `sources(.realization).descendants(.definition).texts()` path
serve the same definition.  A `definition` predicate/fact is included only
as a structural link in the old graph; it is not treated as an extra LEX6
semantic field.  The mapping is therefore an explicitly labelled
`entry/headword/definition` subset, not full TEI/LIFT interoperability.

`--profile rich` is separate.  It keeps the same plain-text projection while
representing each definition as mixed text plus a nested inline element in
LEX6 and as nested source occurrences in LEX5.  It is source-rich rendering
evidence only; it must not be combined with the flat byte or timing rows.

## Measured boundaries (after authorization)

The finite measured mode keeps these rows separate:

* build and complete artifact size;
* archive open (metadata/index/directory validation only);
* full `verifyAll` (all page digests, decompression, packet decode and semantic
  validation);
* cold entry load (page digest, decompression, packet decode and validation);
* warm typed-field selection plus render, after the entry is loaded;
* exact and prefix lookup, including every returned hit and a consumed digest;
* raw, adaptive, and forced bzip3 LEX6 compression on the same generated
  inputs.

Old LEX5 has no compressed entry pages, so its source-backed load/render
  boundary is reported as its own labelled control observation.  It is not
  silently presented as equivalent to LEX6 cold decompression.  Normal Zig
  allocation remains enabled; native bzip3 allocations are not fabricated as
  Zig allocations and are identified as the codec's accounted admission
  allowance.

The reader never receives expected answers or a query schedule.  Expected
digests are built independently from the generated input, while every hit,
spelling, form (when present), selected identity, rendered byte, and snippet
byte is consumed into the observed digest.  Any mismatch fails the run.

## Commands

No-clock smoke (N=32):

```text
python3 src6/bench/run.py --mode smoke --records 32
```

No-clock preparation (N=2048, all three LEX6 codec modes):

```text
python3 src6/bench/run.py --mode prepare --records 2048 --distribution mixed
```

Measured mode is intentionally refused until the root task supplies the
explicit quiet gate:

```text
python3 src6/bench/run.py --mode measure --quiet-gate ROOT-EXPLICIT-QUIET-GATE
```

Every compilation places `-O MODE` before both `-Msrc6` and `-Msrc5`; source
and binary manifests are captured before and after each run.  The wrapper
does not use shell timing or process elapsed time as reader latency.

The accepted gated runs are copied into `src6/bench/evidence/` with their
complete archives, runner binary, raw logs, and provenance.  The measured
warm render/snippet rows are retained as raw observations; on this clock
their totals are near resolution and are not a basis for precise warm-speed
ratios.  The cold row is an in-process fresh entry load over memory-resident
archive bytes, not a disk-cold test.

## After-source-scope evidence

After root's frozen `SourceIndex` ownership fix, the same ReleaseFast
`N=2048` matrix was run once for flat/mixed, rich/mixed, and flat/prose, with
all codecs, two warmups, and seven repetitions.  The original baseline
directories are untouched.  The retained after-scope stages are:

```text
src6/bench/evidence/after-source-scope/flat-mixed/
src6/bench/evidence/after-source-scope/rich-mixed/
src6/bench/evidence/after-source-scope/flat-prose/
```

The rich/mixed before/after build and full-verify observations are single
observations (nanoseconds):

| lane / codec | baseline build | after build | baseline full verify | after full verify |
| --- | ---: | ---: | ---: | ---: |
| frozen LEX5 native | 10,440,583 | 10,916,000 | 3,524,666 | 3,547,334 |
| LEX6 raw | 212,261,292 | 2,890,958 | 169,048,375 | 3,281,583 |
| LEX6 adaptive | 227,677,875 | 23,450,583 | 177,428,292 | 13,252,458 |
| LEX6 forced bzip3 | 233,298,333 | 23,275,500 | 180,527,333 | 13,962,375 |

The exact same raw rich/mixed harness was also run once at each scaling point:

| N | old build | LEX6 raw build | old full verify | LEX6 raw full verify |
| ---: | ---: | ---: | ---: | ---: |
| 256 | 1,659,959 | 568,083 | 1,005,584 | 651,625 |
| 512 | 2,508,209 | 684,792 | 893,083 | 852,792 |
| 1024 | 5,005,042 | 1,785,667 | 1,815,792 | 1,568,834 |
| 2048 | 10,916,000 | 2,890,958 | 3,547,334 | 3,281,583 |

The scaling stages are retained under
`src6/bench/evidence/after-source-scope/scaling-{256,512,1024}/`.  Build and
full verify are separate single observations; the N=2048 row is copied from
the retained rich/mixed matrix stage.  These rows are a bounded check of the
source-map ownership fix, not a complexity fit.

All 12 corresponding `N=2048` artifacts (three profiles × frozen LEX5,
LEX6 raw, adaptive, and forced bzip3) were checked against the untouched
baseline for both complete byte count and SHA-256, and every pair was
identical.  The full 12-row byte/SHA ledger is in
`src6/reviews/benchmark.md`.  The after-scope source manifest is stable at
`083c2c147b1b91ea6e78bd9ae85b7ed288d17d6d0ad3fea7a80f1c4571065cbc` before
compile, after compile, and after each runner.
The earlier baseline manifest differs because it predates the frozen
source-scope and query-context/compile-contract revisions; this did not alter
the fixture or wire inputs.

The cold boundary did not change: it is a fresh selected-entry load over
memory-resident archive bytes, including digest, decompression, packet decode,
and semantic validation, not a disk-cold read.  The old source-backed control
has no compressed entry-page boundary and is a narrower, differently admitted
operation.  Do not infer a new cold comparison, a universal startup result,
or a general speed claim from this rerun.  Flat timing swings are retained in
the raw logs and are not treated as causal evidence.
